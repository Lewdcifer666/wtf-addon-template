# Reliability contract

This is the current engineering contract. Deployment revisions, approvals and
observed acceptance evidence belong in the private migration checkpoint; source
documentation alone never proves that a build is installed or a task succeeded.

## Daily pipeline

Private interpretation must run before the earliest discovery that consumes it.
The existing rotator always occupies one of the five enabled task slots and
stages the four morning or four later targets. Rotation changes enabled flags,
not the authorization of interpretation or research. Never force a missed run.
Native task tools, actual complete-source interpretation, active recomputation,
research use and publication must each be observed independently.

The trusted research worker returns a code-owned `search_policy`: exact generic
query, `daily-primary` request ID and matching preference indexes. Tasks must
copy this binding unchanged. Only recognized public vocabulary can enter the
provider query. A signed original-intent alias enforces one provider invocation
per genre/Berlin date across sessions and public-head changes. An ambiguous
outcome consumes the reservation and remains held; a different ID cannot retry it.
Wikipedia/TVmaze leads still need the genre's independent public corroboration.

## Bounded transport and recovery

One PC request has a 22-second end-to-end budget, including queue wait, token
acquisition, GitHub reads and pending-result waiting. It expires before the
30-second gateway. Expiry never authorizes another provider invocation or ID.
Expired openings and stale interpretation sources remain immutable in the local
journal but do not repeatedly load old graphs during background reconciliation.

GitHub serializes trusted writes with `queue: max`, without cancelling queued
work. The PC admits at most eight outstanding dispatch identities per ten-minute
window, retains the three-attempt bound per identity and obeys durable quota
cooldowns. Exhausted or ambiguous work remains pending; no alternate credential,
endpoint or writer is permitted. Private logs may include only closed HTTP
operation/status/request-ID/quota metadata, never response bodies or personal data.

The contained host stops admitting calls before planned rollover, lets bounded
in-flight calls drain, and retains independent container deadlines and isolation.
Unexpected supervisor termination and Docker dependency failure are different
failures. A running Windows task does not establish useful service readiness.
Automatic restart beyond an approved trigger requires its own concrete grant.

The private journal has a 100000-file safety limit. Preserve every immutable file
and quota record. Before approaching that limit, disable intake and prepare a
reviewed compatible index/archive migration; never delete records to regain
capacity or roll back to a reader that cannot understand existing records.

## Completion and retained boundaries

Health checks, synthetic fixtures, old-feedback interpretation, active flags and
green reconciliation do not prove the entire system. Acceptance requires genuine
new feedback, automatic interpretation/aggregation, later recommendation effects,
correction/supersession and retraction, and installed-TV observation. Never invent
an opinion to close a gate. Historical denied/ambiguous operations and held legacy
PRs stay untouched. Family expansion remains separate.

Keep six public catalog identities/history and baseline scoring unchanged; keep
raw feedback, learned briefs, queries, mappings and signed evidence private.
Use trusted-main OIDC, protected App-owned publication and existing strict checks.
No OpenAI API, paid overages, public feedback repository, broadened credentials,
unauthenticated tunnel or self-hosted runner is part of this architecture.
